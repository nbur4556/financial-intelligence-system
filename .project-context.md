# Project Context: Financial Intelligence System

## Overview
A local-first financial analysis engine designed to treat personal finances like a business. The system moves beyond simple budgeting to provide "Financial Intelligence" via KPI reporting and variance analysis.

## Core Philosophy
- **Analytical over Restrictive:** Focus on reporting and trend analysis rather than strict spending caps.
- **Decoupled Mapping:** Raw transaction strings $\rightarrow$ Clean Merchant $\rightarrow$ Category. This allows for bulk re-categorization without altering raw data.
- **Local-First & Private:** Data stays in SQLite; only logic and schema are versioned.

## Technical Architecture
- **Stack:** Python (Pandas), SQLite, Jupyter Notebooks.
- **Database Schema:** 
    - `transactions`: Raw ledger of spending.
    - `merchants_mapping`: The source of truth for merchant-to-category relations.
- **Data Flow:** `Bank CSV` $\rightarrow$ `etl.py` (Cleaning/Parsing) $\rightarrow$ `finance.db` $\rightarrow$ `Notebooks` (KPIs).

## Chart of Accounts
- **Fixed Costs (OpEx):** Essential costs of existence (Rent, Utilities, etc.).
- **Variable Costs (Growth/Life):** Discretionary quality-of-life spending.
- **Capital Allocations (Investments):** Wealth-building movements.
- **Debt Service:** Liability reduction.

## Key Performance Indicators (KPIs)
- **Burn Rate:** Avg monthly spend (Fixed + Variable).
- **Savings Rate:** `(Income - Expenses) / Income`.
- **Efficiency Ratio:** `Fixed Costs / Total Income`.
- **Variance:** Comparison against 3-month rolling averages.

## Technical Debt & Resolution Strategy

### 1. Brittle Merchant Cleaning
- **Problem:** Current regex heuristics are fragile and fail on diverse bank formats.
- **Resolution:** Implement a Tiered Matching system:
    - **Tier 1 (Exact):** Check `merchants_mapping` for exact raw string match.
    - **Tier 2 (Fuzzy):** Use normalized string comparison to find existing merchants.
    - **Tier 3 (LLM):** Use an LLM to extract clean merchant names from unknown strings.
    - **Approval:** LLM suggestions enter a "Pending" state for human verification.

### 2. Data Integrity & Mapping
- **Problem:** Transactions are allowed to exist without a valid category mapping.
- **Resolution:** 
    - Enforce strict Foreign Key constraints between `transactions` and `merchants_mapping`.
    - Implement a **Staging Area**: Raw data $\rightarrow$ `staging_table` $\rightarrow$ (Clean/Map) $\rightarrow$ `transactions_table`. 
    - This prevents "unmapped" data from polluting KPI reports.
